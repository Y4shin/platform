# Proto and RPC services

Your plugin's API is a set of Connect-RPC services defined in proto. `buf
generate` turns each service into a typed Rust trait (your backend implements
it) and a typed TypeScript client (your frontend calls it). The proto is also
where each method declares the permissions it requires.

## 1. Define the contract

Proto files live under `plugins/<name>/proto/<name>/v1/`:

```proto
// plugins/events/proto/events/v1/events.proto
syntax = "proto3";
package events.v1;

import "platform/v1/annotations.proto";

service EventService {
  rpc ListEvents(ListEventsRequest) returns (ListEventsResponse) {
    option (platform.v1.requires) = "events:read";
  }
  rpc CreateEvent(CreateEventRequest) returns (CreateEventResponse) {
    option (platform.v1.requires) = "events:read,events:write";
  }
}

message ListEventsRequest {}
message ListEventsResponse {
  repeated Event events = 1;
}
message Event {
  string id = 1;
  string title = 2;
  bool viewer_can_edit = 3;
  bool viewer_can_share = 4;
}
```

The `option (platform.v1.requires)` annotation is **the single source of truth**
for a method's permission set (covered in
[Permissions and access control](./permissions.md)). Leave it off entirely and
the method is ungated — its witness becomes `()`, the no-permission witness.
That's intentional for [public surfaces](./public-surfaces.md), and a mistake
everywhere else, so be deliberate.

## 2. Generate the code

```bash
task sync            # registers the proto in buf.yaml and runs buf generate
# or directly:
pnpm exec buf generate
```

This produces:

- **Rust** — the `EventService` trait and message types, generated by your
  plugin's `build.rs` via `connectrpc-build`. (The scaffold's `build.rs` already
  calls it.)
- **TypeScript** — message types + a Connect-Query client under
  `packages/generated/`, re-exported as `@junius/generated/<plugin>/rpc`. The
  frontend imports from there ([Calling the backend](../frontend/calling-the-backend.md)).

Your `build.rs` also emits the per-method permission aliases:

```rust
// build.rs — after connectrpc_build:
junius_rpc_meta::emit_rpc_requires(&PROTO_FILES)?;
```

```rust
// src/lib.rs — include the generated aliases:
include!(concat!(env!("OUT_DIR"), "/_rpc_requires.rs"));
```

This makes `crate::__rpc_requires::event_service::CreateEvent` resolve to the
`And<EventsRead, And<EventsWrite, ()>>` witness chain matching the annotation.

## 3. Implement the service

You write a marker struct and an `impl` block annotated with
`#[rpc_service(ServiceTrait)]`:

```rust
use std::sync::Arc;
use junius_sdk::{rpc_service, Principal};
use crate::pb;   // generated message types

struct EventRpc;

#[junius_sdk::rpc_service(EventService)]
impl EventRpc {
    async fn list_events(
        &self,
        ectx: EventCtx<crate::__rpc_requires::event_service::ListEvents>,
        _request: OwnedListEventsRequestView,
    ) -> ServiceResult<impl Encodable<pb::ListEventsResponse>> {
        let events = ectx.state.events.list().await?;
        Ok(Response::new(pb::ListEventsResponse {
            events: events.into_iter().map(event_to_proto).collect(),
            ..Default::default()
        }))
    }

    async fn create_event(
        &self,
        ectx: EventCtx<crate::__rpc_requires::event_service::CreateEvent>,
        request: OwnedCreateEventRequestView,
    ) -> ServiceResult<impl Encodable<pb::CreateEventResponse>> {
        let caller = ectx
            .user
            .as_ref()
            .map(|u| u.id)
            .ok_or_else(|| ConnectError::unauthenticated("events.error.auth_required"))?;

        let owner = match request.owner_kind {
            "user" | "" => Principal::User(caller),
            "group" => {
                let gid = GroupId(parse_uuid(request.owner_id, "owner_id")?);
                if !ectx.resources.groups.is_member(gid, caller).await? {
                    return Err(err::group_membership_required());
                }
                Principal::Group(gid)
            }
            _ => return Err(err::invalid_owner_kind()),
        };

        let created = ectx
            .state
            .events
            .create(NewEvent { title: require_nonempty(request.title, "title")?, /* … */ },
                    owner, &ectx.resources.authz)
            .await?;

        Ok(Response::new(pb::CreateEventResponse {
            event: Some(event_to_proto(created)).into(),
            ..Default::default()
        }))
    }
}
```

### What the macro does

`#[rpc_service(EventService)]` rewrites each method so that:

- the `ectx: EventCtx<…>` parameter you wrote becomes an internal
  `__ctx: RequestContext` parameter, and the macro prepends
  `let ectx = <ThatType>::from_rpc(&__ctx)?;` to the body — extracting the
  context, verifying the witness, and building your repositories;
- it emits the real `impl EventService for EventRpc { … }` trait impl;
- compile errors point at *your* code, not generated code.

You keep the alias visible at the call site, which is what lets `junius check`
verify the binding — there is no hidden invocation.

### The witness alias rule

Use the generated alias **directly** as the `P` type parameter:

```rust
ectx: EventCtx<crate::__rpc_requires::event_service::CreateEvent>
```

**Never wrap it in `permissions!(…)`.** The alias is already a built witness;
wrapping it turns the chain head into `And<…>` instead of a `Permission`, which
silently breaks `Has<X>` resolution on repository methods — the repo still
compiles, but the *wrong* methods become reachable. Just name the alias.

## 4. Register the service

In your `Plugin` impl, fold each service into the shared RPC router:

```rust
#[async_trait::async_trait]
impl Plugin for EventsPlugin {
    fn metadata(&self) -> &'static PluginMetadata { &METADATA }

    fn routes(&self) -> Router { Router::new() /* plain-HTTP routes, if any */ }

    fn register_rpc(&self, router: connectrpc::Router) -> connectrpc::Router {
        let router = Arc::new(EventRpc).register(router);
        let router = Arc::new(InviteRpc).register(router);
        Arc::new(CalendarRpc).register(router)
    }
}
```

The host folds every plugin's services into **one** Connect-RPC router served
under `/rpc`, injecting the correct per-plugin context per request.

## The `EventCtx` / `PluginContext` type

`EventCtx<P>` in the examples is your alias for
`PluginContext<EventState<P>, P>`, where `EventState` is your repository bundle:

```rust
use junius_sdk::{PluginContext, PluginCtx};

#[derive(PluginCtx)]
pub struct EventState<P = ()> {
    #[repo] pub events: EventRepo<P>,
    #[repo] pub invites: InviteRepo<P>,
    #[repo] pub signups: SignupRepo<P>,
    #[repo] pub calendar: CalendarRepo<P>,
}

pub type EventCtx<P = ()> = PluginContext<EventState<P>, P>;
```

`#[derive(PluginCtx)]` generates the glue that, per request, resolves the host
resources and caller, verifies the witness `P`, and constructs every `#[repo]`
field typed on `P`. In your handler:

- `ectx.state.events` — a `EventRepo<P>`, so only permission-appropriate methods
  are callable;
- `ectx.user` — `Option<User>`, the caller;
- `ectx.resources` — the capability handles (`authz`, `groups`, `email`,
  `jobs`, …).

## `junius check` keeps it honest

Three static rules guard the RPC surface:

| Rule | Fires when |
| --- | --- |
| `RPC.HANDLER.UNGUARDED` | a bare `impl XService for Y` appears in source (you bypassed the macro) |
| `RPC.SERVICE.UNIMPLEMENTED` | a proto service has no `#[rpc_service]` block |
| `RPC.WITNESS.MISMATCH` | a handler's ctx alias names the wrong method/service |

For an unimplemented service, `cargo run -p junius -- rpc scaffold --plugin
<name>` inserts correctly-shaped `todo!()` stubs for every missing method.
