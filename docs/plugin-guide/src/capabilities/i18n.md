# Internationalization

Every user-facing string goes through a catalog so the platform can render it in
the viewer's locale. There are two catalog flavours: **backend** strings (emails,
iCalendar, RPC errors) and **frontend** strings (everything in the UI). Both are
`.po` files; the tooling is `junius i18n`.

## Backend catalog

Add `i18n/en.po` (and any other shipped locales — `de.po`, `pseudo.po`) under
your plugin root. The msgid is a **stable key**; the msgstr is the
source-language template with `{placeholder}` substitutions:

```po
msgid "events.signup.email.subject"
msgstr "You're signed up for {title}"

msgid "events.signup.email.body"
msgstr "Hi {name},\n\nYou're confirmed for \"{title}\".\n\nSee you there!"
```

Wire the codegen into `build.rs`:

```rust
junius_i18n_build::generate(junius_i18n_build::Options::new("events"))?;
```

Then in `src/lib.rs`:

```rust
junius_sdk::i18n_catalog!();   // pulls in the generated `messages` + `catalog`

#[async_trait::async_trait]
impl Plugin for EventsPlugin {
    // …
    fn register_i18n(&self, b: &mut junius_sdk::LocalizerBuilder) {
        catalog::register(b);
    }
}
```

`i18n_catalog!()` emits one **typed struct per msgid**, with one `&str` field per
`{placeholder}`. You render against the recipient's locale:

```rust
let l = ctx.localizer.for_stored(job.recipient_locale.as_deref());
let subject = l.t(messages::EventsSignupEmailSubject { title: &event.title });
```

The payoff is compile-time safety:

- a missing placeholder → **compile error**,
- a misspelled key → **compile error**,
- a translator typo in `de.po` that introduces a placeholder `en` doesn't have →
  **build error** with file:line spans.

### Recipient locale outside a request

Jobs and `.ics` feeds run with no caller. Capture the locale at **enqueue time**
and carry it through the payload (see
[Background jobs and email](./jobs-and-email.md)):

```rust
#[derive(Serialize, Deserialize)]
pub struct SendSignupConfirmation {
    // …
    #[serde(default)]
    pub recipient_locale: Option<String>,
}
```

`None` falls back to the deployment default.

### RPC errors → codes, not English

Never send an English error string from a handler — it bypasses the catalog.
Use a stable `<plugin>.error.<code>` id as the `ConnectError` message; arguments
go after a `:` (e.g. `events.error.field_required:title`). The frontend maps the
code to a localized string. The pattern lives in `plugins/events/src/lib.rs`
(`mod err`) and `plugins/events/frontend/src/errors.ts` (`useEventsError`).

### Don't translate machine metadata

iCalendar `PRODID` and similar RFC-mandated metadata are not translatable —
leave them as the English string. User-entered data (event title, description)
is pass-through and needs no wrapping.

## Frontend catalog

Wrap user-facing strings with Lingui macros imported **directly** from
`@lingui/react/macro` (the SDK can't re-export them — the babel plugin only
transforms calls whose import source it recognizes):

```tsx
import { Trans, useLingui } from '@lingui/react/macro';

export function EventsListPage() {
  const { t } = useLingui();
  return (
    <>
      <h1><Trans>Events</Trans></h1>
      {/* for props that need a plain string (placeholder, aria-label): */}
      <Input placeholder={t`Filter events…`} />
    </>
  );
}
```

Expose a `loadI18n` loader from your plugin's `src/index.ts`:

```ts
/// <reference types="vite/client" />
import type { CatalogLoader } from '@junius/sdk';

const catalogs = import.meta.glob<{ messages: Record<string, string> }>('./i18n/*.po');

export const loadI18n: CatalogLoader = async (locale) => {
  const importer = catalogs[`./i18n/${locale}.po`];
  return importer ? importer() : { messages: {} };
};
```

`junius sync` picks this up automatically — your plugin appears in
`platform/frontend/src/generated/i18n-catalogs.ts` and the host wires it into the
`<I18nProvider>`.

For zod schema messages, build the schema inside the component (memoized on `t`)
so error strings flow through the active locale — see [Forms](../frontend/forms.md).

## Extract, translate, check

```bash
junius i18n extract              # scan source → update each catalog's .po
junius i18n check                # validate every catalog (BE + FE) parses + complete
junius i18n check --check-drift  # CI mode: also fail if extract would change anything
```

Translators edit the `*.po` files. The **pseudo-locale** gate is your safety
net: under `pseudo`, every msgid renders as a diacritic-substituted form of
itself, so any plain English text showing through is an **unwrapped string** —
vitest and Playwright catch these as regressions. Wrap every string and the
pseudo gate stays green.
