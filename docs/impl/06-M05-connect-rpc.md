# M05 — Connect-RPC End-to-End

> **Status:** 🚧 Planned.

## Goal

Plugins define services in `.proto` files. `buf generate` produces Rust server stubs (`connect-rs`) and a TypeScript client (`@bufbuild/protoc-gen-es` + `@connectrpc/protoc-gen-connect-es`) per plugin. The `hello` plugin gets a `HelloService.Greet` RPC; its frontend page calls it via `@connectrpc/connect-query`. This is the **v0 cut** — beyond this point we're hardening, not building new capability shapes.

## Why now

RPC closes the missing limb of the design: the wire contract. After M05, every later capability (persistence, permissions, ownership, cross-plugin) extends a working RPC layer rather than introducing it. Doing this *before* the DB layer means M06+ can reason about RPC method permission checks without backtracking.

## Scope (in)

### Workspace-level proto setup

```
proto/
└── platform/
    └── v1/
        ├── annotations.proto          # option (platform.requires) = "..."
        └── common.proto               # shared types: UserId, ResourceId, Timestamp wrappers
```

`annotations.proto` defines the custom method option:

```proto
syntax = "proto3";
package platform.v1;

import "google/protobuf/descriptor.proto";

extend google.protobuf.MethodOptions {
  // Comma-separated permission names required to invoke this method.
  string requires = 50000;
}
```

At M05, `option (platform.requires)` is *declared* but **not enforced** — enforcement lands in M07 with the permission system. The annotation existing now means later milestones don't have to re-cut every proto file.

### Buf configuration

- `buf.work.yaml` (already in M00, now populated):
  ```yaml
  version: v1
  directories:
    - proto
    - plugins/hello/proto
  ```
- `proto/buf.yaml` — minimal module config for the shared protos.
- `plugins/hello/proto/buf.yaml` — module config for the hello plugin's protos.
- `buf.gen.yaml` at workspace root — generation config:
  ```yaml
  version: v2
  plugins:
    # Rust outputs land in each plugin's OUT_DIR via build.rs
    # (Not in this file — see "Rust codegen approach" below.)

    # TypeScript outputs into @junius/generated
    - remote: buf.build/bufbuild/es
      out: packages/generated/src/proto
    - remote: buf.build/connectrpc/es
      out: packages/generated/src/proto
  ```

### Rust codegen approach

Per-plugin `build.rs` invokes `connect-rs`'s codegen against the plugin's protos:

```rust
// plugins/hello/build.rs
fn main() {
    connect_rs_build::Builder::new()
        .protos(&["proto/hello/v1/hello.proto"])
        .protos_includes(&["../../proto", "proto"])
        .compile()
        .unwrap();
}
```

This places generated code in the plugin's `OUT_DIR`, kept out of the plugin source tree (matching the design's "no generated code in plugin source trees" rule).

The plugin's `src/lib.rs` includes the generated stubs:

```rust
mod gen {
    include!(concat!(env!("OUT_DIR"), "/hello.v1.rs"));
}
```

### TypeScript codegen approach

Buf is invoked by `junius sync` (and explicitly by `junius proto regen`, an alias). Output goes to `packages/generated/src/proto/<plugin>/v1/`.

Per-plugin barrel (`packages/generated/src/plugins/<name>/index.ts`) is written by `junius sync`:

```ts
// Generated by `junius sync` — do not edit.
export { rpc } from './rpc';
export { METADATA } from './metadata';
export type { Permission } from './permissions';   // empty union at M05; populated at M07
```

`packages/generated/src/plugins/<name>/rpc.ts` is also written by `junius sync` (narrow per-plugin namespace from M09; at M05 it just re-exports the full service descriptor):

```ts
import { HelloService_Greet } from '../../proto/hello/v1/hello_connect';

export const rpc = {
  HelloService: {
    greet: HelloService_Greet,
  },
} as const;
```

`@junius/generated/package.json` `exports` field updated by `junius sync` to include the per-plugin subpaths.

### Buf vendoring

`junius` ships a small "tool installer" that downloads the pinned `bufbuild/buf` release on first use into `~/.cache/junius/bin/buf-<version>`. Plugin authors don't install buf themselves.

Implementation: `tools/junius/src/tooling/buf.rs` checks for the cached binary, downloads + verifies SHA-256 if missing, returns its path. `junius sync` and `junius proto regen` shell out to it.

### Hello plugin updates

`plugins/hello/proto/hello/v1/hello.proto`:

```proto
syntax = "proto3";
package hello.v1;

import "platform/v1/annotations.proto";

service HelloService {
  rpc Greet (GreetRequest) returns (GreetResponse) {
    // Not enforced until M07.
    option (platform.requires) = "";
  }
}

message GreetRequest {
  string name = 1;
}

message GreetResponse {
  string message = 1;
}
```

`plugins/hello/src/lib.rs` gains a `HelloServiceImpl`:

```rust
struct HelloServiceImpl;

#[async_trait::async_trait]
impl gen::HelloService for HelloServiceImpl {
    async fn greet(
        &self,
        req: gen::GreetRequest,
    ) -> Result<gen::GreetResponse, connect_rs::Error> {
        Ok(gen::GreetResponse {
            message: format!("Hello, {}!", req.name),
        })
    }
}

impl Plugin for HelloPlugin {
    fn routes(&self, _resources: PluginResources) -> Router {
        Router::new()
            .merge(connect_rs::router_for(HelloServiceImpl))
            .route("/ping", get(|| async { "pong" }))
    }
}
```

The host nests the returned router under `/rpc/hello` (for the Connect routes) and `/h/hello` (for the bare HTTP route). Mounting logic lives in `platform/src/server.rs`; it uses `metadata().mount` to know the prefixes.

### Frontend updates

`plugins/hello/frontend/src/routes/pages/HelloPage.tsx` uses Connect-Query:

```tsx
import { useQuery } from '@connectrpc/connect-query';
import { rpc } from '@junius/generated/hello';

export function HelloPage() {
  const { data } = useQuery(rpc.HelloService.greet, { name: 'world' });
  return <Card><Stack gap="md"><h1>{data?.message}</h1></Stack></Card>;
}
```

Shell wires up the Connect transport in `main.tsx`:

```tsx
import { TransportProvider } from '@connectrpc/connect-query';
import { createConnectTransport } from '@connectrpc/connect-web';

const transport = createConnectTransport({ baseUrl: '/' });

<TransportProvider transport={transport}>...</TransportProvider>
```

### `junius dev` extensions

- Watch `**/*.proto` → on change, run buf generate and trigger a Vite/cargo restart of the affected side.
- Watch `**/plugin.toml` → on change, run `junius sync` and trigger restart.

Implementation: `notify` crate for file events; debounce 200ms; only restart the affected child.

### CI extensions

- `buf format --diff` (must be clean).
- `buf lint` (must be clean).
- `buf breaking --against <main ref>` (must report no breaking changes against `main`).

## Scope (out)

- No permission enforcement on RPCs. `option (platform.requires)` is parsed by buf and round-tripped to the generated code, but the interceptor that checks it lands in M07.
- No narrow per-plugin RPC namespace yet — at M05 the generated `rpc.ts` exposes the full service. Narrowing per `[dependencies.<dep>].rpc_methods` lands in M09.
- No streaming RPCs. Unary only for v1.
- No `connect-go` or `connect-kotlin` — Rust + TS only.

## Library choices — confirm with user before starting

| Choice | Proposed default | Rationale | Downstream milestones to update if changed |
|---|---|---|---|
| **Connect Rust server** | `connect-rs` | Locked by design ([../design/03-backend.md](../design/03-backend.md) §3.3) | Every RPC milestone |
| **Connect TS client** | `@connectrpc/connect-web` | Locked by design | Every FE milestone from M05 |
| **Connect Query integration** | `@connectrpc/connect-query` | Best TanStack Query bridge | Every FE milestone from M05 |
| **TS proto codegen** | `@bufbuild/protoc-gen-es` + `@connectrpc/protoc-gen-connect-es` | Locked by design (referenced in §3.3) | Every FE milestone from M05 |
| **Rust proto codegen** | `connect-rs`'s `connect-rs-build` helper invoked from each plugin's `build.rs` | Generated code stays in `OUT_DIR`, no source-tree pollution | M07 (buf custom-options plugin extends this) |
| **Buf installation** | `junius` downloads pinned release into `~/.cache/junius/bin/buf-<version>` | No developer setup friction | M12 (`buf breaking` in CI uses the same cached binary) |
| **Buf release pin** | Latest `bufbuild/buf` stable at impl time | Reproducibility | If we hit a buf regression, pin to the prior version |
| **File watcher in `junius dev`** | `notify` crate (cross-platform) | Standard Rust file-system event library | M06 (extends watcher with migration triggers) |

## Verification

```bash
# Sync (runs buf generate)
target/release/junius sync --config dev/platform.toml

# Generated artifacts exist
ls packages/generated/src/proto/hello/v1/                # hello_pb.ts, hello_connect.ts
ls plugins/hello/target/.../OUT_DIR/                      # hello.v1.rs (Rust)

# Build & run
target/release/junius dev --config dev/platform.toml &

# Direct RPC test (Connect-Web supports POST with JSON body)
curl -fsS http://127.0.0.1:8080/rpc/hello.v1.HelloService/Greet \
  -H 'Content-Type: application/json' \
  -d '{"name":"world"}'
# → 200 {"message":"Hello, world!"}

# Browser test: open /p/hello → "Hello, world!" displayed.
# This goes through the FE: useQuery → Connect-Web → Vite proxy → Axum → connect-rs.

# Breaking-change detection
# (a) Edit the proto to rename a field — buf breaking should fail in CI.
# (b) Type-check the FE — TS should fail because the field rename invalidates the call site.

# Tests
cargo test -p hello-plugin
cargo test -p platform
pnpm --filter @junius/plugin-hello test
pnpm exec buf breaking --against '.git#branch=main'
```

End of M05 = **v0 cut**. The architecture's shape is fully proven: a plugin contributes manifest + Rust + protos + frontend; `junius` composes everything; a single binary serves the whole stack. Everything beyond this milestone adds depth, not new capability shapes.
