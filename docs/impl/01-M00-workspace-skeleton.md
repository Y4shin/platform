# M00 — Workspace Skeleton

## Goal

A repo a developer can `git clone`, `nix develop`, and then `cargo build` + `pnpm install` successfully — with nothing actually running. Pure scaffolding, with the full toolchain provided by a Nix flake.

## Why now

Establishes the directory layout from [../design/05-repository-and-deployment-layout.md](../design/05-repository-and-deployment-layout.md) §5.1 before any code uses it. Cargo and pnpm both refuse to operate without a workspace declaration; getting these in place first means M01 onward can add crates/packages without re-litigating layout. The Nix flake gives every contributor (and CI) the same Rust / Node / pnpm / buf / biome versions out of the box.

## Scope (in)

### Top-level files

- `flake.nix` — pins the dev toolchain (Rust via `rust-overlay` reading `rust-toolchain.toml`, Node 24, pnpm, biome, buf, plus `git`/`openssl`/`pkg-config`). Single source of truth for tool versions.
- `flake.lock` — generated by `nix flake update`; commits the resolved nixpkgs + `rust-overlay` revisions for reproducibility.
- `.envrc` — `use flake`; lets direnv users get the shell automatically when entering the repo.
- `Cargo.toml` — workspace root declaring members `platform`, `tools/junius`, `crates/junius-sdk`, `crates/junius-sdk-macros`, and a marker-managed region under `members` for plugins (populated by `junius sync` from M03 onward). `[workspace.dependencies]` pre-pins shared deps so member crates use `serde.workspace = true` instead of duplicating versions.
- `pnpm-workspace.yaml` — lists `platform/frontend`, `packages/*`, `plugins/*/frontend`.
- `package.json` (root) — minimal; declares the workspace, pins `packageManager`, holds dev scripts (`lint`, `format`, `typecheck`).
- `tsconfig.base.json` — shared TS compiler options; each package's `tsconfig.json` extends this.
- `buf.work.yaml` — declares `proto/` as a buf module (and `plugins/*/proto` from M05). Empty for now.
- `rust-toolchain.toml` — pin Rust 1.87.0 with `rustfmt`/`clippy`. The flake reads this so the dev shell and CI use the same toolchain.
- `biome.json` — formatter + linter config; `recommended` ruleset, 2-space, 100-col, single-quote JS, no trailing commas in JSON.
- `.editorconfig` — UTF-8, LF, 2-space indent for JS/TS/JSON/YAML/TOML/MD, 4-space for Rust (matches `rustfmt` default).
- `.gitignore` — Rust (`target/`), node (`node_modules/`), `dist/`, `.env`, OS junk, `.junius-cache/`. Does **not** ignore `.sqlx/` (committed per design §10.2) or `platform/src/generated/` (those are committed even though generated, for buildability outside the dev shell).
- `LICENSE` — full AGPL-3.0 text from gnu.org.
- `README.md` — short project description with pointers to `docs/design/` and `docs/impl/`; mentions `nix develop` as the way to get a shell.
- `.github/workflows/ci.yml` — runs on PR + push to main inside the Nix dev shell:
  - `nix develop --command cargo fmt --check`
  - `nix develop --command cargo clippy --workspace --all-targets -- -D warnings`
  - `nix develop --command cargo build --workspace`
  - `nix develop --command pnpm install --frozen-lockfile`
  - `nix develop --command pnpm exec biome ci`
  - `nix develop --command pnpm run typecheck`
  - Uses `DeterminateSystems/nix-installer-action` + `magic-nix-cache-action`, plus `Swatinem/rust-cache` for the cargo target dir.

### Empty crates / packages

Every workspace member exists but contains nothing meaningful:

- `platform/` — `Cargo.toml` declaring a binary with `src/main.rs` containing `fn main() {}`.
- `tools/junius/` — `Cargo.toml` declaring a binary; `src/main.rs` with `fn main() {}`.
- `crates/junius-sdk/` — `Cargo.toml` library; `src/lib.rs` empty.
- `crates/junius-sdk-macros/` — `Cargo.toml` with `proc-macro = true`; `src/lib.rs` empty.
- `platform/frontend/` — `package.json` (name `@junius/shell`, private), no source.
- `packages/sdk/` — `package.json` (name `@junius/sdk`, private), `src/index.ts` exporting nothing.
- `packages/design/` — `package.json` (name `@junius/design`, private), `src/index.ts` exporting nothing.
- `packages/generated/` — `package.json` (name `@junius/generated`, private), `src/index.ts` exporting nothing. `exports` field empty; populated by `junius sync` later.

### Directory placeholders

- `plugins/` — empty (no plugins yet); a `.gitkeep` to keep it in git.
- `proto/` — empty (will hold `platform/v1/annotations.proto` in M05); `.gitkeep`.
- `docs/design/` — existing, untouched.
- `docs/impl/` — this folder.

### What's deliberately absent

- No `dev/platform.toml` yet — the deployment config schema lands in M01 along with the parser.
- No Axum, no `Plugin` trait, no `clap` setup — those start in M01/M02.
- No `tailwind.config.ts` — comes in M04 with the first frontend code.
- No Docker Compose — comes in M06 when we need Postgres + Authentik.

## Scope (out)

- Anything that requires writing or running code beyond `fn main() {}`. If a milestone doc later mentions a config file or template literal, it gets added then.
- `dev/platform.toml` — needs the manifest schema, which lands in M01.

## Library choices (locked at M00)

| Choice | Locked value | Notes |
|---|---|---|
| Toolchain provisioning | **Nix flake** via `nixpkgs/nixos-unstable` + `oxalica/rust-overlay` | Single source of truth for tool versions; same shell in CI and locally. `flake.lock` pins the resolved revisions. |
| Rust toolchain version | **1.87.0** (with `rustfmt`, `clippy`), edition **2024** | Pinned in `rust-toolchain.toml`; the flake reads it. |
| Node | **24.x** (active LTS) | From nixpkgs `nodejs_24`. `package.json` `engines.node` enforces. |
| pnpm | **11.x** (current stable from nixpkgs `pnpm`) | `packageManager` field pins the exact patch version. |
| Biome | nixpkgs default (currently 2.4.x); also pinned as a `pnpm` devDep for non-Nix fallback | `recommended` ruleset, 100-col, 2-space, single quotes. |
| buf | nixpkgs default (currently 1.69.x) | Provided in the dev shell so junius CLI doesn't have to vendor it. |
| CI runner | **GitHub Actions** with `DeterminateSystems/nix-installer-action` + `magic-nix-cache-action` + `Swatinem/rust-cache` | Same Nix shell as local dev; reproducible. |
| Workspace dep-version policy | Centralised `[workspace.dependencies]` for shared crates (serde, tokio, anyhow, thiserror, tracing, uuid, chrono, axum, sqlx, syn/quote/proc-macro2). | Member crates use `.workspace = true`. Add a new pin here when more than one member crate needs it. |

None blocking. The design's open questions don't intersect M00.

## Verification

```bash
# Fresh clone
git clone <repo>
cd junius

# Enter the dev shell (all tools pinned by the flake)
nix develop

# Inside the shell:
rustc --version    # → rustc 1.87.0
node --version     # → v24.x
pnpm --version     # → 11.x

# Rust side compiles
cargo build --workspace

# Linters pass
cargo fmt --check
cargo clippy --workspace --all-targets -- -D warnings

# JS side installs + lints
pnpm install
pnpm exec biome ci
pnpm run typecheck

# Binaries produced
ls target/debug/junius target/debug/juniusd

# CI is green on the PR that introduces this milestone.
```

Expected outcome: every command above exits 0. Nothing is runnable beyond `cargo run -p platform` (which prints nothing and exits — it's `fn main() {}`) and `cargo run -p junius` (likewise).
