# 4. Frontend

## 4.1 Stack

- **React + TypeScript.**
- **TanStack Router** for routing — code-based, fully type-safe, composable.
- **TanStack Query** + `@connectrpc/connect-query` for data fetching, caching, and mutations.
- **Vite** as the build tool.
- **SPA mode by default; SSR optional via M23.** The platform sits behind authentication, so SSR/SEO is unnecessary for most surfaces — but deployments that want server-rendered first paint (public events, signup), CDN-fronted FE, or independent FE/BE scaling can flip the topology. See §4.5.

## 4.2 Why this stack over SvelteKit / Next.js / Leptos

- **Code-based routing fits plugin composition natively.** Routes are data; each plugin exports a route subtree that `junius` concatenates. File-based routers (SvelteKit, Next App Router, Nuxt, Remix) require build-time codegen shims to compose plugins.
- **Best-in-class ecosystem for SPA-heavy UI.** Rich text editors, data grids, drag-and-drop, complex forms — all most mature on React.
- **Largest hiring pool.**
- **Connect-RPC integration is first-party** via `connect-query`.
- **Leptos rejected** for production: 0.x churn, thin component ecosystem, niche hiring.
- **SvelteKit rejected** despite better per-component DX: file-based routing fights the plugin model.

## 4.3 Plugin contract (frontend side)

Each plugin is also a pnpm workspace package (`@junius/plugin-<name>`) that exports:

```ts
// plugins/speakers/frontend/index.ts
export { routes } from './routes';              // TanStack Router subtree
export { SpeakerPicker, SpeakerCard } from './lib'; // public components
export { createSpeakersClient } from './rpc';    // Connect-RPC client factory
export type { Speaker, SpeakerId } from './types';
```

## 4.5 Frontend delivery modes (M23)

Two supported topologies; deployments pick one in `[build] frontend`:

### Embedded (default)

The SPA assets are bundled into `juniusd` via `rust-embed`. One process, one image, one health check. Best for self-contained single-binary deployments and the M11 example.

```
browser ── juniusd (SPA + API + RPC)
```

### Split (M23)

Two containers:

- `juniusd` — built with `[build] frontend = "none"`, headless API/RPC only. Browser routes return a structured 404; the FE container handles them.
- `frontend-ssr` — Node host package (`platform/frontend-ssr/`). Hand-rolled SSR atop `react-dom/server's `renderToPipeableStream` + a per-request TanStack Router; proxies `/api`, `/h`, `/rpc` to juniusd; forwards inbound cookies through an `AsyncLocalStorage`-backed Connect interceptor so SSR runs as the requesting user.

```
browser ── frontend-ssr ─┬─ SSR HTML
                          └─ /api /h /rpc proxy ── juniusd
```

Why hand-rolled instead of TanStack Start: our `routeTree` is code-generated by `junius sync` (plugin contract); Start expects file-based routing under `src/routes/`. Spike findings recorded in `docs/impl/25-M23-optional-ssr.md` "Library choices".

Either topology is fully supported; switching is a deploy-time change, not a hot operation.
